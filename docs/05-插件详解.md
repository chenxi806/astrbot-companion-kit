# 插件详解

## 一、growth_card：判断卡注入 + 记录

**它做什么**

- 每轮把 `card.companion.txt` 追加到用户消息末尾（`<GrowthCard>` 边界）
- 每轮把 `{ts, umo, user, assistant}` 写进 `raw/YYYY-MM-DD.jsonl`
- 只在私聊生效

**为什么走「用户消息」而不是 system**

AstrBot 的 `on_llm_request` 在人格注入之前触发，往 `system_prompt` 里 append 会被覆盖。`extra_user_content_parts` 是 add-only 通道，和 livingmemory 一致。

**命令**

- `/card` 查看
- `/card reload` 重读文件
- `/card log 内容` 往事件流追加
- `/card review` 列待审提案

**注意**

- 卡文件按 mtime 缓存，改完 `render.py` 立即生效，不用重启
- `record_raw` 关掉后，复盘就没有素材了

## 二、lorebook：人格分片

**它做什么**

把人格里「不常驻」的部分拆成条目，按关键词 + 概率 + 冷却注入：

```
命中关键词 → 冷却检查 → 掷概率 → 按 priority 排序 → 取前 N 条 → 注入
```

**为什么这样设计**

- 人格写得越细，越不该全量常驻：token 贵，注意力还会衰减
- 概率带来随机性：同一条「女仆形态」不是每次都在
- 冷却防止重复：刚提过的事不会连着两轮又提

**条目类型**

| 类型 | 条件 | 用途 |
|---|---|---|
| 关键词条目 | `keys` 命中 | 被夸、吃醋、答疑、认真模式 |
| 随机池 | `keys: []` + `random_pool: true` | 示范对话、日常小片段 |
| 群聊专用 | `group_only: true` | 对外人的语气 |

**命令**：`/lore`、`/lore list`、`/lore test 文本`

## 三、galgame：关系阶段

**它做什么**

用「认识天数 + 互动条数 + 共同事件」算阶段，每轮注入一句行为提示：

```
【关系阶段】亲近
明显偏心：会吃醋、会主动找他、会护短。想他了也绕着说，不直接承认。
```

**阶段推进**

- 条件不够不跳级
- 到门口但事件不够 → 提示她安排一次小事件（带 A/B/C 选项）
- 用户回 A/B/C → 共同事件 +1
- 亲密之后锁死：`allow_confession` 打开且正式告白才进下一段

**为什么不用好感分**

分数会让人想刷。用天数 + 条数 + 事件，更接近真实关系：聊得多不等于关系近，得有共同经历。

**命令**：`/stage`

## 四、state：心情/精力

**它做什么**

两个 0–1 的慢变量：

- 每天漂移一次：随机 ±0.1 + 向 0.6 回归
- 深夜降精力，早上回一点
- 对话微调：被夸 +0.03，被冷落 −0.05，每天上限 ±0.1
- 注入一句定性描述 + 行为建议（不报数字）

**whim 池**

按状态过滤后随机挑一条，注入「你刚想起：……」。每天最多 2 次、间隔 ≥5 小时。

**为什么**

随机性来自内部状态，而不是随机换措辞。同一句话，心情好和心情闷时反应不一样，才像活的。

**命令**：`/state`

## 五、daily_ritual：早晚安

**它做什么**

- 08:00 叫起床，00:00 催睡
- 用当前人格 + 判断卡 + 最近两天对话生成，不是固定文案
- 随机角度（拿吃的引诱 / 赖床 / 装困……）
- 避开上次说过的话
- 重启或休眠错过时间，90 分钟内补发

**注意**

- 只发文字，不发语音（避免和语音插件冲突）
- 主动消息在部分平台有限制，发不出去时看日志
- 和别的「每日问候」插件可能重复，二选一

**命令**：`/ritual status`、`/ritual test morning|night`

## 六、weekly_review：复盘

**它做什么**

按「事件 → 洞察 → 判断」三层整理：

1. 读 `store.json`、最近 14 天事件、最近 7 天对话
2. 产出洞察（允许错）
3. 判断变更必须引用洞察，否则拒绝
4. 写 `proposals/`，私聊通知
5. 用户回「同意」→ 写入；「驳回」→ 丢弃

**触发**

- 周日 21:00，或累积 50 条新对话
- 有待审提案时跳过（14 天后自动丢弃重生成）

**自动维护**

- 未强化的判断每周 −0.01 置信度（最低 0.3，可关）
- 低于 0.45 标 `stale`

**命令**：`/review status|show|now|reject`

**设计取舍**

- 不让模型直接改 store：所有变更先落提案，人点头才写
- 判断必须引用洞察：防止一次情绪改判断
- 单次变更上限 3 条：宁可少改兜底
