# 世界书（Lorebook）技术说明

> 世界书解决的是“人格里塞不下、但偶尔该知道”的设定：场景、关系、口癖来源、世界观名词。
> 它不是人格，不进常驻提示词；**命中关键词才注入，一轮最多 3 条**。

插件：`astrbot_plugin_lorebook`
数据：`memory/lorebook.json`（**唯一生效源**）
人读版：`memory/lorebook.md`（不生效，需同步）
状态：插件数据目录下 `state.json`（记录每条上次注入时间，用于冷却）

---

## 一、文件格式

```json
{
  "version": 1,
  "updated": "2026-10-28",
  "entries": [
    {
      "label": "艾莉丝模式",
      "id": "alice",
      "probability": 0.4,
      "cooldown_minutes": 20,
      "priority": 9,
      "random_pool": false,
      "keys": ["艾莉丝", "エリス", "红发", "剑术少女"],
      "content": "艾莉丝·伯雷亚斯·格雷拉特，红发红瞳……"
    }
  ]
}
```

### 字段

| 字段 | 类型 | 必填 | 作用 |
|---|---|---|---|
| `id` | string | ✅ | 唯一标识；状态、冷却、命令都按它记 |
| `label` | string | — | 只在 `/lore list` 和日志里显示 |
| `keys` | string[] | ✅（`random_pool` 除外） | 关键词，**子串匹配**，不是分词 |
| `content` | string | ✅ | 真正注入的正文，建议 60~200 字 |
| `probability` | 0~1 | — | 命中后再掷一次骰子；默认 1.0 |
| `cooldown_minutes` | int | — | 同一 id 在该时间内不重复注入；0 = 不冷却 |
| `priority` | int | — | 排序用，越大越优先；默认 1 |
| `random_pool` | bool | — | `true` = 不靠关键词，作为随机池候选 |
| `group_only` | bool | — | `true` = 只在群聊用；默认私聊 |

## 二、匹配与选择算法（按代码实际行为）

每轮收到用户消息 `text` 后：

1. **分组过滤**
   `group_only` 与当前会话类型不符的直接跳过。

2. **关键词匹配**
   `matched = [k for k in keys if k in text]`
   - 纯子串匹配，**区分大小写**，不做分词、不做同义词
   - 英文关键词建议同时写小写与大写形式
   - `random_pool: true` 的条目不要求命中

3. **无命中处理**
   没命中且不是 `random_pool`、不是 `group_only` → 跳过。

4. **冷却**
   `now - last_inject < cooldown_minutes * 60` → 跳过。
   状态按 `id` 存在 `state.json`。

5. **概率**
   `random.random() > probability` → 跳过。
   注意：**先冷却、后概率**，冷却期内连掷骰子的机会都没有。

6. **排序**
   候选记 `(priority, 命中关键词数量, entry)`，按前两项降序排序。

7. **截断**
   取前 `max_entries` 条，默认 **3**（配置项 `max_entries`）。
   所以“条目越多，单条越难出现”是真实效果，不是错觉。

8. **注入**
   作为 `extra_user_content_parts` 附在用户消息后，带起止标记；
   每轮开始前会先移除上一轮注入的旧块，避免累积。

9. **热加载**
   按 `(mtime_ns, size)` 缓存；文件一改，下一轮自动重读，**不用重启**。

## 三、写作原则

1. **一条只讲一件事**：一个场景、一个关系、一个名词。
2. **正文写“怎么反应”，不写“是什么”**：
   - 差：`艾莉丝是红发少女。`
   - 好：`她吃醋会直接说「我不喜欢」，说完自己先脸红。`
3. **关键词要真的会出现在聊天里**：口语、昵称、错别字都算。
4. **别把人格搬进世界书**：语气、底线、称呼属于人格；世界书只放“偶尔需要想起来”的东西。
5. **控制总量**：20~40 条比较舒服；超过 60 条，单条命中率会明显下降。
6. **同一关键词不要给多条**：会互相抢名额，按 `priority` 决胜负，另一条几乎永不出现。
7. **概率别都写 1.0**：高频场景 0.6~0.9，稀有设定 0.2~0.4。

## 四、md ↔ json 同步

- **只有 `lorebook.json` 生效**；`lorebook.md` 是人读版。
- 改 md 后必须跑 `工具/md_to_json.py`（或双击 `世界书同步.bat`）。
- 每条 md 必须有 `- id：xxx` 行，否则同步不进去。
- 反方向（改 json 后更新 md）没有自动工具时，手动同步或重跑渲染脚本。

## 五、命令

| 命令 | 作用 |
|---|---|
| `/lore` | 看条目总数、本轮注入上限 |
| `/lore list` | 列出所有 id、关键词数、概率 |
| `/lore test 文本` | 用一段文本试命中，忽略概率，看会选中哪些 |

`/lore test` 是排查“为什么这条不出现”的第一工具。

---

## 六、排查清单

| 现象 | 先查 |
|---|---|
| 完全不出现 | 关键词是否真的出现在消息里（子串、大小写） |
| 偶尔出现 | `probability` 是否太低；`cooldown_minutes` 是否太长 |
| 被别的条目挤掉 | `/lore test` 看排序；同关键词条目是否 `priority` 更高 |
| 改了没反应 | 是不是改的 `lorebook.md` 而不是 `.json` |
| 重启后状态丢了 | `state.json` 在插件数据目录，不在 `memory/` |
| 注入内容重复 | 检查是否有两条内容几乎一样、关键词重叠 |

## 八、和其他系统的边界

| 系统 | 管什么 | 和世界书的区别 |
|---|---|---|
| 人格 | 常驻语气、底线、称呼 | 每轮都在，不靠关键词 |
| 判断卡 | 关于“你”的事实与规则 | 按场景注入，但内容是关系判断 |
| 世界书 | 设定、场景、名词、口癖来源 | 命中才出现，可以很多条 |
| 示例池 | “怎么说”的句子 | 管语气，不管设定 |
| 梗库 | 网络梗释义 | 管词义，不管反应 |

一句话：**人格是“她是谁”，判断卡是“她记得你什么”，世界书是“她偶尔想起的设定”，示例池是“她怎么说话”。**
