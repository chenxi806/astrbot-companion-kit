# 为什么需要这套东西

## 一、先说结论：模型不会因为你聊得多而记住你

大模型有两个事实，决定了「AI 伴侣」这件事的难点：

1. **权重是冻住的。** 你聊一万句，模型参数一个都不变。它不会「越来越懂你」，除非有人把关于你的信息写进它这次能看到的文本里。
2. **每次对话都是重新读一遍。** 它所谓的「记得」，本质是每次请求把历史聊天记录重新塞给它。窗口装得下就记得，装不下就截断。

所以「成长」不可能发生在模型里。它只能发生在**模型之外**——一份每次对话前都会被读到的档案。

这套工具做的就是这份档案，以及围绕它的读写机制。

## 二、三层记忆，各管什么

| 层 | 存什么 | 谁写 | 例子 |
|---|---|---|---|
| 事实 fact | 确认过、基本不变 | 人 | 生日、忌口、称呼 |
| 判断 judgment | 从相处里得出的结论 | 复盘 | 「累了先陪着，别讲道理」 |
| 洞察 insight | 还没定论的观察 | 复盘 | 「他最近反复确认我还在不在」 |

判断和事实都会注入对话；洞察不注入，只用来「攒够证据再升成判断」。

为什么要有洞察这一层？因为**一次情绪不该改判断**。他说一次「别烦我」，可能只是今天累；如果直接写成「他不喜欢我黏人」，这条判断会一直错下去。先记成洞察，第二次出现再升级，才稳。

## 三、人格为什么要拆成「核心 + 世界书」

人格写在一个 9000 字的 system prompt 里，会有两个问题：

- **贵**：每轮都传 9000 字，token 一直烧。
- **钝**：模型对长 prompt 中段的注意力会衰减，越靠后的规则越容易被忽略。

拆成两层之后：

- **核心**（≤2000 字）：身份、说话规则、底线、关系底色。每轮都在。
- **世界书**：女仆形态、被夸协议、答疑模式、吃醋……每条带关键词和概率，命中才注入。

好处是：人格看起来更厚（条目可以写得很细），但每轮实际注入的只有命中的两三条；而且「这次想起了哪几条」本身带来随机性。

## 四、状态机：随机性来自状态，不是措辞

「随机换句式」很快就会被看穿，因为它没有内在逻辑。这套用的是慢变量：

- `mood`（心情）、`energy`（精力），每天漂移 ±0.1，向 0.6 回归
- 深夜降精力，早上回一点；被夸涨心情，被冷落掉心情
- 状态低 → 句子短、不闹；状态高 → 主动、黏人

再加一个 `whim` 池：一组小事（楼下的猫、突然想吃的店），按状态过滤后随机冒出来。她不是「随机说一句话」，是「此刻真的想起了这件事」。

## 五、关系阶段：让「发展」有刻度

认识 → 熟悉 → 亲近 → 亲密（恋人未满），每段有明确的条件（天数、互动条数、共同事件）。

- 条件不够，关系不会因为聊得多就跳级
- 到阶段门口但事件不够，会提示她制造一次共同经历
- 再往后锁死：要正式告白才进下一段

这样「在一起」是一个事件，不是一句台词。

## 六、这套东西不能做什么

- 不能让模型真的产生记忆或意识
- 不能保证注入的内容一定被遵守（模型仍有随机性）
- 不能替代平台能力：主动消息受平台限制，图片/语音要额外插件
- 不能自动变好：档案要人维护，错了会一直错

理解这四条，才不会对它有不切实际的期待。
