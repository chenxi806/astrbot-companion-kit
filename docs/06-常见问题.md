# 常见问题

## 安装与加载

**Q: 重启后插件没加载？**

看 `data/logs/astrbot.log` 里有没有：

```
Loading plugin astrbot_plugin_growth_card ...
```

没有的话，检查：

1. 文件夹名和 `metadata.yaml` 的 `name` 是否一致（必须完全一样）
2. 文件夹里有没有 `main.py`
3. 日志里有没有 `Failed to load plugin` 和报错堆栈

**Q: 提示缺少依赖？**

六个插件都只用标准库 + AstrBot 自带 API，不需要额外 `pip install`。
如果报 `ModuleNotFoundError: astrbot...`，说明插件没放对目录，或者 AstrBot 版本低于 4.24。

**Q: 改了代码要重启吗？**

要。AstrBot 不热加载插件代码。但 `store.json` / `lorebook.json` / `card.companion.txt` 这些**数据文件**改完即生效（按 mtime 读）。

## 记忆与判断卡

**Q: `/card` 说「判断卡还没生成」？**

1. 检查 `card_path` 是否指向真实存在的文件
2. 手动跑一次 `python render.py`
3. 检查 `store.json` 是否是合法 JSON（少逗号最常见）

**Q: 改了 store.json 但她还在用旧卡？**

跑 `python render.py`。注入的是 `card.companion.txt`，不是 `store.json`。

**Q: 判断卡进群了吗？**

默认不会。`scope: private` 时只在私聊注入。群里她看不到你的个人信息。

**Q: 记忆会不会越积越多、拖慢回复？**

判断卡是渲染出来的固定长度（几十行），不会随记忆增长。`raw/` 会变大，但只在复盘时读。

## 复盘

**Q: `/review now` 回了「跑完了」，但我没收到通知？**

两种可能：

1. 平台主动消息被限流/折叠（QQ 官方机器人常见）
2. `umo` 解析错

先看 `proposals/` 下有没有文件——有就说明生成成功，只是通知没到。
可以直接 `/review show` 看内容，回「同意」照样能写入。

**Q: 提案里的判断全被跳过了？**

因为没引用洞察。这是设计：判断变更必须能追溯到「想明白了什么」。
如果模型总是不引用，检查提示词是否被改坏，或者把 `_normalize` 的校验放宽。

**Q: 置信度自己掉了？**

周衰减：没被强化的判断每周 −0.01。不想要就在配置里关 `decay_enabled`。

**Q: 能不用模型、纯手动复盘吗？**

可以。直接改 `store.json`，跑 `render.py`。复盘插件只是自动化，不是必需。

## 关系/状态

**Q: 关系一直停在「认识」？**

阶段按 `raw/` 里的天数算，不是按你聊了多少句。装好当天不可能跳级，至少等 3 天。

**Q: 她怎么突然变冷淡/变黏了？**

看 `/state`。心情/精力是慢变量，低的时候句子会短、少闹。

**Q: 心情一直很低？**

可能被负面词反复扣分。可以把 `NEGATIVE_WORDS` 改窄，或手动改 `state.json`。

## 平台相关

**Q: QQ 官方机器人能主动发消息吗？**

能，但有限制：需要用户近期互动过，且有频次限制。发不出去时 API 可能仍返回 200，但消息不显示——这是平台行为，不是插件 bug。

**Q: Telegram / WebChat 呢？**

同样适用，`umo` 自动从最近私聊解析。

**Q: 群聊里她会用判断卡吗？**

不会。群聊只注入 `group_only` 的世界书条目（对外人的语气）。

## 数据与隐私

**Q: 数据存在哪？会上传吗？**

全部在本地 `companion_memory/` 和 `plugin_data/`，没有云同步。
但注入的内容会随请求发给模型提供方——这是任何 LLM 应用都一样的。

**Q: 怎么备份？**

复制整个 `companion_memory/` 即可。`store.json` 是纯文本，可以直接看、直接改。

**Q: 怎么回滚？**

改之前备份 `store.json`；判断有 `status` 字段，把 `archived` 改回 `active` 就恢复了。

**Q: 能多个人格共用一套吗？**

不建议。`scope` 字段可以区分 `companion` 和 `dev`，但状态文件是单份的。
