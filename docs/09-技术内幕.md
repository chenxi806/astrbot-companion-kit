# 技术内幕：文件、插件与数据流

> 这份文档补的是“能跑起来之后，想知道它到底怎么运作”的部分。
> 如果只想知道怎么用，看 `03-快速开始.md`；想改人格/世界书，看 `04`、`08`。

---

## 一、仓库目录与线上目录的对应关系

仓库是**模板 + 插件源码**，不是可直接跑的实例。真实运行时，AstrBot 从自己的数据目录读：

| 仓库路径 | 线上真实路径 | 说明 |
|---|---|---|
| `plugins/<name>/` | `E:\bot\instances\<id>\core\data\plugins\<name>\` | 复制过去才生效 |
| `memory-template/` | `memory\` | 模板，需要按自己情况填 |
| `config/*.json` | `E:\bot\...\core\data\config\` | 插件配置 |
| `docs/` | 不参与运行 | 纯文档 |

改仓库里的插件源码**不会**自动生效，必须部署 + 重启。

## 二、一次对话的完整链路

```
QQ 消息
  → qq_official 适配器
  → 预处理（STT / 图片理解）
  → 事件总线
  → 插件钩子（on_llm_request，按注册顺序）
       ├─ lorebook：命中关键词的条目
       ├─ memory_card：判断卡 companion
       ├─ voice_pool：抽 4 条示例
       ├─ meme_glossary：命中的梗释义
       └─ mode_switch：当前模式提示
  → AstrBot 组装 messages
  → provider（deepseek-flash）
  → 插件钩子（on_llm_response）
       ├─ private_companion：表情/动作清洗、回复复核
       └─ tts：按需合成
  → 发送
```

### 注入顺序与预算

| 顺序 | 内容 | 预算 |
|---|---|---|
| 1 | 核心人格 | 全文（建议 ≤2200 字） |
| 2 | 状态/日程 | 少量 |
| 3 | 判断卡 | ≤1800 字 |
| 4 | 世界书 | ≤3 条 |
| 5 | 梗库 | ≤2 条 |
| 6 | 示例池 | 4 条 |
| 7 | 长期记忆 | 少量 |
| 8 | 聊天历史 | 最近若干轮 |
| 9 | 作者注 | 最后一行 |

越靠后，模型越敏感。示例池放在后段，是为了让“怎么说”压过“说什么”。

## 三、插件职责表

| 插件 | 职责 | 关键钩子 | 数据 |
|---|---|---|---|
| `memory_card` | 判断卡渲染与注入 | `on_llm_request` | `memory/card/store.json` |
| `card_review` | 每周提取、审批 | 定时 + 命令 | `pending.json` |
| `voice_pool` | 示例池抽取、`/good` `/bad` | `on_llm_request` + 命令 | `voice_pool/examples.jsonl` |
| `pool_review` | 池审、月审 | 定时 + 命令 | `examples.jsonl` |
| `mode_switch` | 角色模式状态机 | `on_llm_request` + 命令 | `modes/state.json` |
| `lorebook` | 关键词命中注入 | `on_llm_request` | `memory/lorebook.json` |
| `meme_glossary` | 梗库命中注入 | `on_llm_request` | `memory/memes.json` |

> 其余插件（TTS、相册、主动消息等）不属于这套记忆系统，按需安装。

## 四、关键数据结构

### 判断卡 `store.json`

```json
{
  "facts": [{"id": "f1", "text": "生日 1 月 15 日", "confidence": 0.9, "source": "2026-10-20"}],
  "judgments": [{"id": "j1", "text": "他累的时候先接情绪", "confidence": 0.7, "evidence": ["..."]}],
  "taboos": [{"id": "t1", "text": "不拿他家人开玩笑", "confidence": 1.0}],
  "insights": [{"id": "i1", "text": "他最近睡得晚", "confidence": 0.4}]
}
```

- `facts` / `judgments` / `taboos` 进卡；`insights` 不进卡，只等升级。
- 新判断 `confidence` 从 0.6 起；冲突时旧条目 `status: "superseded"`，不要并存。

### 示例池 `examples.jsonl`

一行一条：

```json
{"id":"e1","text":"……","likes":2,"picked":5,"score":3,"status":"active","tags":["撒娇"]}
```

- `likes` / `picked` / `score` / `status` 是旧字段，保留兼容。
- 上限到了只降级，不删除。

### 世界书 `lorebook.json`

见 `08-世界书详解.md`，这里不重复。

## 五、人格写入（最容易踩的坑）

人格**不在文件里生效**：

1. 改 `memory/core-persona.txt`
2. 跑 `工具/write_core_persona.py` 写进 `data_v4.db` 的 `personas` 表
3. 重启 AstrBot

只改文件不写库 = 没改。备份文件会落在 `backup-persona-日期-时间/`。

## 六、配置项

| 文件 | 关键项 |
|---|---|
| `memory_card` | `max_chars`（卡片长度上限）、`inject_empty` |
| `lorebook` | `lore_path`、`max_entries` |
| `meme_glossary` | `max_entries`、`glossary_path` |
| `voice_pool` | `pick_count`、`max_pool`、`min_score` |
| `mode_switch` | `timeout_minutes`（默认 10） |

配置改动需要重启；数据文件改动多数热读。

## 七、模型侧参数（经验值）

| 参数 | 值 | 说明 |
|---|---|---|
| 模型 | `deepseek-flash` | 1M 上下文，便宜、够快 |
| 温度 | 0.9 | 角色扮演需要一点随机 |
| top_p | 0.9 | 与温度配合，别同时拉满 |
| 最大输出 | 按场景 | 日常 300~500 token 足够 |

温度低于 0.6 会明显变“背台词”；高于 1.1 开始跑题。

## 八、验证与排错

```powershell
# 新系统自检（判断卡、示例池、审查、部署一致性）
python 工具/测试_新系统.py

# 世界书命中测试
/lore test 今天好累

# 看插件是否加载
Select-String -Path <astrbot.log> -Pattern "astrbot_plugin_lorebook"
```

日志路径：`E:\bot\instances\<id>\core\data\logs\astrbot.log`

常见现象：

| 现象 | 原因 |
|---|---|
| 改了没生效 | 改的是模板/备份，不是线上文件 |
| 人格没变 | 没写库或没重启 |
| 世界书不命中 | 关键词子串不匹配、概率、冷却 |
| 回复变机械 | 温度太低，或示例池被清空 |
| 插件加载失败 | `__pycache__` 残留、依赖缺失 |

## 九、为什么仓库里没有“全部内容”

1. **人格、判断卡、世界书正文是个人内容**：仓库只给模板和示例，避免把私人聊天/关系细节公开。
2. **运行时依赖不打包**：模型权重、Python 环境、AstrBot 本体、数据库都不在仓库里。
3. **插件按需**：TTS、相册、主动消息等属于可选扩展，和记忆系统解耦。
4. **文档按层拆分**：`02` 讲怎么跑，`03`/`04`/`09` 讲数据结构，本文讲内部实现；不是漏写，而是没堆在一页里。

如果要完整复刻，需要：AstrBot 实例 + 本仓库插件 + 自己的 `memory/` 内容 + 模型 API Key。
